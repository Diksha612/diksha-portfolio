# Certificate Guide

## A. Folder structure

| Path | Purpose |
|---|---|
| `public/certificates/internships/` | Internship certificate files |
| `public/certificates/courses/` | Course certificate files |
| `src/data/certificates.json` | The single manifest the site and validator both read |
| `scripts/validate-certificates.mjs` | Pre-deployment validator |
| `reports/certificate-validation-report.md` | Report generated by the validator |

**Everything inside `public/` becomes publicly downloadable once deployed.** A file at `public/certificates/courses/a.pdf` is served at `https://your-site/certificates/courses/a.pdf`, so the manifest `filePath` is `/certificates/courses/a.pdf` (no `public` in the URL). Never treat this folder as private storage.

| Flutter & Dart (course) | `public/certificates/courses/flutter-dart-udemy.pdf` |

The real filename and extension must match what the manifest says. Supported: PDF, JPG, JPEG, PNG.

## C. Upload procedure

1. Attach the original files to Claude when asked (PDF or image).
2. Copy each file into the matching folder above, using the expected filename (or any name, then update `filePath`).
3. Run `npm run validate:certificates`.
4. For more than one certificate on one entry, add one extra record per file (see H) with the same `linkedEntryId`.

## D. Configuration (`src/data/certificates.json`)

| Field | Meaning |
|---|---|
| `id` | Unique, lowercase-hyphenated |
| `category` | `internship` or `course` |
| `linkedEntryId` | `id` of an entry in `src/data/experience.js` or the `courses` list in `src/data/education.js` |
| `title` | Shown on the card |
| `organization` | Issuer as printed on the certificate; `null` hides it |
| `filePath` | Browser URL path, starting with `/` |
| `fileType` | `pdf`, `jpg`, `jpeg` or `png`; must match the extension |
| `status` | `pending`, `uploaded` or `verified` (below) |
| `verificationUrl` | Real verification link or `null`. Shows "Verify Certificate" only when set |
| `credentialId` | Printed credential ID or `null`; shown as text |
| `issueDate` | `YYYY-MM-DD` or `null` |

Statuses are for your tracking only: **pending** = file not added yet; **uploaded** = file added and reviewed for privacy; **verified** = checked with the issuer (needs a `verificationUrl` or `credentialId`). The public site shows a certificate only if the file really loads, whatever the status.

## E. Preview and download behavior

On load the site sends a same-origin `HEAD` request per file (cached). If the file is missing, is HTML, or fails to load, the card is hidden and the entry stays visible. PDFs preview in an `<object>`, images in an `<img>`. "Enlarge Certificate" opens a modal (Esc or backdrop closes, focus is trapped and restored, page scroll locked). Download is a normal link to the real file. Some mobile browsers show only page one of inline PDFs; the modal and download still work.

To replace a certificate, overwrite the file (same name) or change `filePath`/`fileType`. To remove one, delete the file and its record.

## F. Privacy review

Check each file before publishing. Items to look at in the current set: the Microsoft Azure certificates print a Student ID and your email; the SYNTECXHUB certificate has a QR code and an organization registration number; certificate IDs appear on the Cadd/Prodigy and Udemy certificates. If you want any hidden, tell Claude which and ask for a reviewed redacted copy; keep the original privately and approve the redaction first.

## G. Validation

From the project folder run `npm run validate:certificates`. It prints results and writes `reports/certificate-validation-report.md`. Exit code 1 means a blocking error. Fixes: **Missing file** → place the file at the stated path; **Unsupported format** → use PDF/JPG/JPEG/PNG; **File/type mismatch** → align `fileType` with the extension; **Invalid configuration** → fix the named field. Warnings (not verified, organization unset) do not block.

## H. Adding or replacing certificates later

1. Copy the file into `public/certificates/internships/` or `courses/`.
2. Add (or edit) a record in `src/data/certificates.json` with a unique `id`, the right `linkedEntryId`, `filePath` and `fileType`.
3. Run `npm run validate:certificates`.
4. Commit and push; Vercel redeploys. No React component changes are needed.

## I. Deployment

Run validation before every deploy. After deploying, open the live URL and check that each certificate previews, enlarges, closes with Esc, and downloads the right file.
